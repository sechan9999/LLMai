Built for power users who care about privacy

Six tools, two interfaces, one principle: your code never leaves your machine.

🔒

100% local

Runs against a local Ollama instance. No outbound API calls, no telemetry, no account required.

🤖

Real agentic loop

Up to 20 iterations of plan → tool → observe per turn. The model chains reads, edits, and tests on its own — not just one-shot chat.

🛡️

Explicit-permission writes

Reads and searches auto-run. write_file, edit_file, and run_command require explicit approval — configurable per tool.

🔧

Six built-in tools

read_file · write_file · edit_file · list_files · search_code · run_command — all path-sandboxed to your workspace.

🔄

Works with any model

Native function-calling for Qwen and Llama 3.x; XML-based fallback for Gemma, Phi, and Mistral. The agent picks the right mode automatically.

🌐

CLI and Web UI

Rich terminal REPL for fast iteration, plus a dark-mode browser UI over WebSocket for visual permission prompts and tool traces.

🖥️

Cross-platform

Native PowerShell on Windows, POSIX shell on macOS and Linux. Path traversal and a destructive-command blocklist are enforced everywhere.

📦

Context compression

When the conversation grows past ~50k tokens, older turns are auto-summarized so long sessions don't blow your model's context window.

How it works

A small, readable Python loop — not a framework.

1

You ask in plain language

Type into the REPL or the Web UI: "add pagination to the products endpoint and update the tests."

2

Ollama plans the next step

The agent calls your local model with the conversation and a list of tools. The model decides whether to read a file, run a command, or answer.

3

Tools run, sandboxed to your workspace

Read-only tools execute immediately. Anything that mutates state pauses for your approval — in the terminal or as a card in the Web UI.

4

Loop until the task is done

Tool results feed back into the model. It plans the next step, runs another tool, and repeats up to 20 times until it has a final answer.

Run it locally in under a minute

Pick the install path you prefer. Make sure Ollama is running and a model is pulled.

git clone https://github.com/sechan9999/LLMai.git
cd LLMai
pip install -e .

# In another terminal:
ollama serve
ollama pull qwen2.5-coder

# Launch the Web UI (or run `vixcode` for CLI):
vixcode-server
# → open http://127.0.0.1:7777
git clone https://github.com/sechan9999/LLMai.git
cd LLMai

# Make sure Ollama is reachable on the host
docker compose up -d

# → open http://127.0.0.1:7777

Need a smaller model? Try ollama pull gemma3:4b — vixcode auto-detects that Gemma needs the XML tool-calling fallback and switches.
