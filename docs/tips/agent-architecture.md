# Claude Code 에이전트 아키텍처

> **확인 시점**: 2026-05  
> **확인 방법**: Ollama + Qwen 2.5 Coder로 Claude Code 엔진 교체 실험

---

## 왜 유용한가

챗봇과 AI 코딩 에이전트의 차이는 "도구 사용 가능 여부"가 아니라 **루프 구조**에 있다.
이 구조를 이해하면:
- 에이전트가 왜 여러 단계를 자율로 수행하는지 알 수 있다
- 프롬프트를 어떻게 써야 에이전트가 잘 동작하는지 알 수 있다
- 직접 유사한 에이전트를 만들 수 있다

---

## 3계층 구조 [FR-01]

Claude Code의 핵심은 3개 계층이 조합된 단순한 구조다.

```
사용자 입력
     ↓
┌─────────────────────────────────────┐
│  계층 1: 도구 시스템 (Tool System)   │
│  ~40개 JSON 스키마 정의 도구         │
│  read, write, edit, bash, search... │
└──────────────────┬──────────────────┘
                   ↓
┌─────────────────────────────────────┐
│  계층 2: LLM 엔진                   │
│  관찰 → 판단 담당                   │
│  (OpenAI-compatible API)            │
└──────────────────┬──────────────────┘
                   ↓
┌─────────────────────────────────────┐
│  계층 3: API 프록시                  │
│  스트리밍 · 권한 · 컨텍스트 압축    │
└─────────────────────────────────────┘
```

**[확인됨]** Ollama 교체 실험에서 계층 2를 로컬 LLM으로 대체하여 동일 구조 검증.  
**[추측]** Claude Code의 정확한 도구 수(~40개)는 공식 미공개.

## while(true) 에이전트 루프 [FR-02]

### 챗봇 vs 에이전트 비교

| 구분 | 챗봇 | 에이전트 |
|------|------|---------|
| 실행 방식 | 1회 응답 후 종료 | 목표 달성까지 루프 반복 |
| 도구 사용 | 없음 | 파일·셸·검색 등 실행 |
| 자율성 | 없음 | 다음 행동을 스스로 결정 |
| 종료 조건 | 항상 즉시 | 명시적 완료 선언 or 최대 반복 |

### 루프 플로우

```
while(목표 미달성):
  ┌─────────────────────────────────┐
  │  1. observe                     │
  │     현재 파일·명령 결과 파악     │
  ├─────────────────────────────────┤
  │  2. judge                       │
  │     LLM이 다음 행동 결정        │
  │     → 도구 실행? or 최종 응답?  │
  ├─────────────────────────────────┤
  │  3. act                         │
  │     도구 실행 or 텍스트 응답     │
  └─────────────────────────────────┘
       ↓ (도구 실행인 경우 반복)
  최대 20회 후 강제 종료
```

이 루프가 챗봇과의 **결정적 차이**다.
챗봇은 "버그를 수정해줘"라고 하면 코드를 보여주기만 한다.
에이전트는 파일을 읽고, 수정하고, 테스트를 실행하고, 결과를 확인하는 전 과정을 자율 수행한다.

## 실시간 스트리밍 파싱 [FR-04]

### 왜 중요한가

AI 응답이 빠르게 느껴지는 이유는 **TTFT(Time To First Token)** — 첫 토큰이 도착하는 속도다.
에이전트는 토큰을 수신하면서 동시에 텍스트인지 도구 호출인지 파싱한다.

### 이중 파싱 모드

```
토큰 스트림 수신 중...
        ↓
┌───────────────────────────────┐
│  모델이 tool use를 지원하는가? │
└───────────┬───────────────────┘
            │
    ┌───────┴───────┐
    ↓               ↓
네이티브 모드    XML 폴백 모드
OpenAI tools   <tool_call>{...}</tool_call>
파라미터 파싱   텍스트에서 JSON 추출
```

**[확인됨]** `server/agent_ws.py`에서 직접 구현:
- `qwen2.5-coder`, `llama3.x` → 네이티브 function calling
- `gemma3`, `phi3` → XML 태그 파싱 폴백

## 컨텍스트 압축 전략 [FR-05]

### 문제

대화가 길어지면 LLM의 컨텍스트 윈도우가 가득 찬다.
Claude Code는 이 문제를 **자동 압축**으로 해결한다.

### 전략

```
현재 대화 토큰 수
        ↓
  13,000 토큰 여유 유지
        ↓ (초과 시)
  요약 에이전트 호출
  (별도 LLM 호출로 이전 대화 요약)
        ↓
  요약본으로 대화 교체 후 계속
```

**[추측]** 13,000 토큰 버퍼 수치는 역분석 추정값. 공식 미확인.  
**[확인됨]** `/compress` 명령으로 수동 트리거 가능.

### 실용 팁

- 긴 세션에서 `/compress`를 먼저 실행하면 성능이 유지된다
- 에이전트가 갑자기 이전 맥락을 잊는다면 압축이 일어난 것
